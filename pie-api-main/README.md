# PIE - API

## API for the Portable Isolated Environment system

Backend service for the **Portable Isolated Environment (PIE)** exam
system. It is a [FastAPI](https://fastapi.tiangolo.com/) application that manages
courses, exams, sessions, users and exam devices, receives real-time monitoring data
(logs, screen-share, and pub/sub events) from student devices, and serves that data to
the [WebApp](../WebApp-main) proctoring dashboard used by teachers and admins.

## Architecture

| Component | Technology | Purpose |
|---|---|---|
| API | FastAPI (Python 3.11) | REST + WebSocket + SSE endpoints |
| Database | MySQL 8 | Courses, exams, sessions, users, devices, submissions |
| Cache / broker | Redis | Pub/sub for the `/pie` topic and live screen-share signaling |
| Log store | Elasticsearch + Kibana | Archival and search of device/session activity logs |
| Malware scanning | ClamAV | Scans uploaded exam files and student submissions |
| Admin UI | phpMyAdmin | Browser access to the MySQL database (dev only) |

All services are orchestrated with Docker Compose (`docker-compose.yml`).

## Getting started

### Requirements

- Docker and Docker Compose
- `openssl` (used once by the setup script to generate secrets)

### First-time setup

Generate a `.env` file with unique, randomly-generated secrets (JWT signing key,
MySQL passwords) for this deployment:

```bash
./scripts/setup.sh
```

This only needs to run once per deployment. It creates `.env` from scratch and is
safe to re-run — it will never overwrite an existing `.env`. See
[Configuration](#configuration) for what it generates.

### Run with Docker Compose

```bash
docker compose up --build
```

This starts the API together with MySQL, Redis, Elasticsearch, Kibana, ClamAV, and
phpMyAdmin. The API reloads automatically on code changes (`uvicorn --reload`, with
the repo mounted as a volume).

| Service | URL |
|---|---|
| API | http://localhost:8000 |
| API docs (Swagger UI) | http://localhost:8000/docs |
| phpMyAdmin | http://localhost:8080 |
| Kibana | http://localhost:5601 |
| Elasticsearch | http://localhost:9200 |

### Run locally without Docker

```bash
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
uvicorn app.api.main:app --reload --host 0.0.0.0 --port 8000
```

You will need your own MySQL, Redis, Elasticsearch and ClamAV instances reachable at
the hosts/ports configured in `.env`.

## Configuration

Configuration is read from environment variables, defined in `.env` and loaded by
`app/core/config.py` (the app) and directly by `docker-compose.yml` (the `db` and
`phpmyadmin` services). `.env` is never committed — see [First-time
setup](#first-time-setup). `.env.example` documents every variable without real
values.

| Variable | Description |
|---|---|
| `APP_PORT` | Port the API listens on |
| `JWT_SECRET_KEY` / `JWT_ALGORITHM` | Secret and algorithm used to sign login tokens — generated by `scripts/setup.sh` |
| `MYSQL_ROOT_PASSWORD` | MySQL root password — generated by `scripts/setup.sh` |
| `MYSQL_USER`, `MYSQL_PASSWORD`, `MYSQL_DB`, `MYSQL_HOST`, `MYSQL_PORT`, `DATABASE_URL` | MySQL connection (`MYSQL_PASSWORD` generated by `scripts/setup.sh`) |
| `REDIS_HOST`, `REDIS_PORT`, `REDIS_URL` | Redis connection, used for pub/sub and screen-share signaling |
| `CELERY_BROKER_URL`, `CELERY_RESULT_BACKEND` | Celery task queue (backed by Redis) |
| `CLAMAV_HOST`, `CLAMAV_PORT` | ClamAV daemon used to scan uploads |
| `ELASTICSEARCH_HOST`, `ELASTICSEARCH_PORT`, `ELASTICSEARCH_URL` | Elasticsearch connection for log archival/search |
| `LOG_RETENTION_DAYS` | How long logs are kept in Redis streams before archival |
| `LOG_MAX_STREAM_LENGTH` | Max length of a Redis log stream before trimming |


## Authentication & authorization

Authentication uses JWT bearer tokens (`python-jose`), issued via `POST /users/login`
and passed as `Authorization: Bearer <token>` on subsequent requests.

Three access levels gate the routers in `app/api/main.py`:

- **Public** — `POST /users/login`
- **Authenticated** (`get_current_user`) — most resource routes (sessions, devices,
  submissions, logs, screen-share, session-users, the `/pie` pub/sub endpoints)
- **Teacher or admin** (`get_teacher_or_admin_user`) — course, exam and analytics
  management
- **Admin only** (`get_admin_user`) — `POST /users/create`

## API overview

Interactive, always-up-to-date documentation is available at `/docs` (Swagger UI) and
`/redoc` once the API is running. Main resource groups:

| Prefix | Router | Description |
|---|---|---|
| `/users` | `user.py` | Login, logout, CRUD for user accounts |
| `/course` | `course.py` | CRUD for courses |
| `/course/{course_id}` | `exam.py` | CRUD for exams within a course |
| `/course/{course_id}/{exam_id}` | `session.py` | Exam sessions: create/start/end, exam file upload/download, encryption key, submissions |
| `/session-users` | `session_user.py` | Links a student + device to a session (tap-gated: only the examiner-assigned student on the tapped device, see `docs/tap-gated-student-join.md`); tracks join/leave times |
| `/submission` | `submission.py` | Student submission uploads and per-student session timing |
| `/device` | `device.py` | CRUD for registered exam devices |
| `/logs` | `logs.py` | Ingest and query activity logs per device/session/user/course/exam, live SSE log streaming |
| `/analytics` | `analytics.py` | Aggregated log summaries, time series, and course/exam hierarchies |
| `/screenshare` | `screenshare.py` | WebSocket signaling (offer/ICE candidates) and relaying for live student screen-share monitoring |
| `/pie`, `/pie/{id}` | `pie.py` | Generic Redis pub/sub publish (`POST`) and subscribe via SSE (`GET`) channel used for real-time device/session events |

### Data model

- **User** — `nmec`, name, email, password (hashed), role (`admin` / `teacher` / student)
- **Course** — `id`, name
- **Exam** — belongs to a course
- **Session** — an exam sitting: join code, room, date/duration, allowed links/students, encrypted exam file + key, start/end state
- **SessionUser** — a student+device pair joined to a session, with join/leave timestamps
- **Device** — a registered exam device (name, last IP/seen/updated)
- **Submission** — a file submitted by a student for a session, with size/MIME type and optional grade

## Real-time features

- **Log streaming** — device and session logs are written to Redis streams and
  archived into Elasticsearch (`streams_service.py`, `elasticsearch_service.py`);
  clients can tail logs live over Server-Sent Events.
- **Pub/sub** — `pubsub_service.py` wraps Redis pub/sub for the generic `/pie`
  broadcast/topic channels used to push events to connected clients.
- **Screen-share** — `screenshare_service.py` relays WebRTC signaling (offers, ICE
  candidates) between a student client and a teacher's monitoring view over
  WebSockets, brokered through Redis.

## Testing utilities

`app/testing/` contains standalone HTML clients (`client.html`, `client_v2.html`) for
manually exercising the WebSocket/SSE endpoints (screen-share, log streaming, pub/sub)
without needing the full WebApp frontend running.
